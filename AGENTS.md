# Omawhite

Local-first whiteboard for Omarchy with export for the agent. Native Rust engine (winit + wgpu), single binary `omawhite`, later fronted by a thin Omarchy shell plugin. User data lives in `~/.local/share/omawhite/`; the control socket is `$XDG_RUNTIME_DIR/omawhite.sock`.

# ARCHITECTURE.md Is a Draft

[ARCHITECTURE.md](ARCHITECTURE.md) is a working draft under construction, not a contract: the real architecture emerges from development. [README.md](README.md) tracks what actually exists — read it first. `§N` references in code and docs point at ARCHITECTURE.md sections. When code and draft diverge, the code is the truth; evolve the draft as decisions actually land.

# Working Style

Scaffolding means minimum: build in small slices, don't implement the whole draft ahead of need. §15 of the draft orders the implementation cuts to de-risk the stack — stay inside the slice at hand.

# Commands

```sh
cargo build
cargo test                    # full suite
cargo test store::            # one module's tests (inline #[cfg(test)] modules)
cargo run                     # most recent board, or a new one
cargo run -- --new            # new board
```

Save, open and the unsaved-work question go through `xdg-desktop-portal`
(any backend with a file chooser; `-gtk` here). The question itself has
no portal and falls back to `zenity`; without it the answer comes back
as a cancel, so nothing is lost.

Headless-ish smoke test (opens a window, renders 3 frames, exits):

```sh
XDG_DATA_HOME=/tmp/omawhite-smoke cargo run -- --socket /tmp/omawhite-smoke.sock --smoke-frames 3
```

# Architecture

Module layout is in the README. The shape that matters:

- **Single instance.** `main.rs` maps CLI flags to an IPC request; if the socket answers, the intent is forwarded and the process exits — only otherwise does it become the main instance and start the winit loop. `--export` and `--shutdown` never spawn a window.
- **Pure core, thin shell.** `doc` (serde data, versioned schema, layers and paint order), `scene` (view + document → SDF prims, frames, the affine that carries a prim, groups and the passes that composite them), `geom` (affine maps, oriented frames), `select` (element frames, hit-testing, handles and the transforms they drive), `bitmap` (image bytes → RGBA8, paste size), `grid`, `theme`, `brush` (the library of sets and presets, a brush's body and the properties that address it, the tip a stroke carries, the pointer's ring), `editor` (tool, held keys, stroke and its tip, pan/zoom gesture, selection and the drag reshaping it, the active layer), `dock`, `palette` (the brush library on the left: the shelves, the grid of icons, the preview), `props` (the brush properties bar and the Advanced layout it drops), `layers` (the panel on the right, its scroll area, and the handle that opens it), `tabs` (the strip, and what a tab gives up when it narrows), `text` (glyph atlas, measure, layout, truncation), `project` (a document's origin and dirty flag), `store` (XDG persistence, blobs, project files), `cli`, and `ipc` are pure and carry the whole test suite. `app` (winit event loop, input routing, socket → event-loop bridge), `gestures` (Wayland `zwp_pointer_gestures_v1` → event-loop bridge), `tablet` (`zwp_tablet_v2` → event-loop bridge, save the frame it accumulates, which is pure and tested), `clipboard` (`wl_data_device` → event-loop bridge), `dialogs` (portal file chooser and message box → event-loop bridge) and `gfx` (the instanced SDF pipelines, image textures, the scratch texture) are the untested shell — keep logic out of them so it stays testable.
- **Frame data flow:** grid + document + live stroke + selection overlay + brush ring + dock + brush palette + properties bar + layers panel + tab strip → `scene`/`select`/`brush`/`palette`/`props`/`layers`/`tabs` prims, gathered in a `scene::Frame`. An image is one prim too: `scene` needs the renderer's blob → texture-slot map to emit it, and `gfx` cuts the frame into runs wherever that slot changes. A glyph is that same textured box with `Prim.uv` naming its cell of the atlas; the atlas is white with alpha for coverage, so `texel * color` is the ink. It has its own slot in `gfx`, never an entry in the blob map. A soft or translucent stroke is a **group** in the frame: `scene::passes` plans, on the CPU where it is tested, a wipe and a draw of its prims into a window-sized scratch texture and one composite box laid back at the stroke's opacity, dropping groups off the viewport; `gfx` only executes the passes. How the prims meet in the scratch is the group's `blend`: `Union` is every channel a max, premultiplied — the union of their coverage, what a swept stroke needs so a soft edge does not bead at its joints — and `Build` is one over the next, what a stamped stroke needs so its dabs pile up. How the finished shape meets what it is laid on is the group's `lands`: `Over`, or `Erase` for a stroke that takes ink away. A crisp opaque stroke — every pencil stroke — never becomes a group.

There is a second surface, the **sheet**, and it is what makes an eraser possible: a raster layer is pixels, and an eraser rubs out that layer and nothing under it. `Frame::sheet` wraps a `Paint` whose strokes include one that erases — and only then, so a paint with nothing to rub out is drawn exactly as it was before — and the pass plan opens the sheet with a wipe, draws or composites every stroke of that paint onto it (an eraser's group laid with `Erase`, which is a plain destination-out), and lays the whole sheet on the window once at full strength, since each stroke's own opacity was spent on the way in. A `Pass` is therefore one shape for all three surfaces: what it draws `Onto` (`Window`, `Sheet`, `Scratch`), the box it wipes first, the `Lay` it puts down before anything else and how that meets what is there, and the prims it then draws. The window's first pass is what clears it, so there is always one; every other surface loads, since a wipe box is what opens the part of it being used. The scratch and the sheet each have a texture slot of their own, like the atlas.

The stroke in progress is painted **inside the document's own frame**, on the layer it is going to land on (`Editor::live_layer`, handed to `document_prims` as a `Live`): that is where it meets the ink already there the way it will at the release, and the only place an eraser has anything to rub. A stroke whose layer holds no paint yet is drawn last, over everything, as it always was — and an eraser there paints nothing at all, which is exactly what it will do when it lands.
- **Documents and tabs.** One tab is a `Project` (document + `Origin` + dirty flag) and the `Editor` driving it: tool, selection and any drag belong to a document, so a tab switch hands nothing on and only re-applies the held modifiers, which are physical. `Origin` decides where `Ctrl+S` writes — `Board(id)` for anything the CLI or the plugin made (they write before the window sees it, and `index.json` is the only file the plugin reads), `File(path)` for a project the user named, `Untitled` until the first save asks. Nothing autosaves: a scene change dirties the tab, a camera change dirties nothing. `open` is never empty — the last tab closing sets `closing` instead, because every accessor assumes a tab in front.
- **Layers.** `Document.layers` is bottom to top and never empty in memory; every element names its layer by id, and `from_json` settles both — a board without layers gets `Layer 1` and its elements join it, an unknown or duplicate id is an error. Paint order is `Document::painted()`: the layers' order, then document order within a layer, hidden layers skipped — `scene` paints through it and `select` hits through it, so the renderer and the pointer never disagree on what is on top. A layer also says what it holds: `Kind::Raster` accumulates, `Kind::Vector` is the one object it was made for. Raster is the default and absent on disk, so a board written before kinds existed opens meaning what it always meant. The active layer is session state on the `Editor`, kept as an id (it survives reorders) and resolved to the top when unset or gone, and picking an element makes its layer active. Where new ink lands is `Editor::ink_layer`: raster joins the active layer when that one takes pixels and opens one above it when it does not (a brush stroke over a vector layer), vector always opens one of its own — so every pencil stroke becomes a layer, and every brush stroke joins the sheet it is painting on. `fresh_layer` is the half that opens and activates; a pasted image calls it directly, since a paste never joins what is already there. What a raster layer accumulates is one element: `Element::Paint` holds a `Vec<Stroke>`, and a brush release pushes onto the paint already on that layer, opening one only when there is none. A `Stroke` is a `path` without an identity — the curves and the ink they were laid with — because the ink belongs to the stroke, not to the object: changing brush mid-painting must not repaint what is already down, and two strokes cannot share one `path`, whose curves are a single chain (`path_prims` would draw the jump between them). `scene` paints and composites a paint stroke by stroke, so painting twice over the same place darkens it as pixels would; `select` frames it around every stroke (`ink_frame`), hits it on any (`ink_hit`) and transforms them all together. A layer and its object go together in both directions: `delete_selection` drops the layers its deletion empties, and `Editor::remove_layer` on the last layer — which always stays — clears what is on it instead of refusing. The kind a stroke asks for is the tool's, read at the release: switching tools cancels the stroke in progress, so it is still the tool that started it. The panel's `+` makes a raster layer, and each card marks what its layer holds — `Row::mark` at the end opposite the eye, a pixel grid or a curve, drawn in `theme.muted` because it is read, never clicked. Layer operations live on `Document` (add above, remove but never the last, move one step, reorder to any index); the editor wraps them and keeps the selection honest (what is hidden or removed leaves it). Dragging a row is `reorder_layer` on the active layer, applied live on every move: the press selects the layer, `Panel::drop_index` names the row under the pointer — a purely positional answer, so the reorder it causes cannot make it oscillate — and `app` holds nothing but the flag saying the pointer is still down. A row paints as a card inside it (the rect is the hit target, the card less the gap between two of them is what is drawn). `Panel::prims` takes a `Lift { index, y, t }`: the card it names is built in its row like any other, then every property is carried `ease(t)` of the way — a longer shadow, an outline mixing to `theme.lifted` (a fixed blue, the one color not derived from the plugin's three), and finally `Prim::transformed` over the card's own prims, contents and all, growing it, turning it clockwise, leaning it toward the canvas and putting it at `y`. It is painted last, over the cards it is passing. `y` is the pointer less the grip the press took, clamped to the rows on show, so the card follows the pointer instead of stepping between rows. Only the clock is `app`'s: `Carry` walks `t` toward whether the button is down, asks for the next frame while it moves, and outlives the release so the card eases back into its row. Everything else the panel eases is a `Coming` — how far it still has to come and how much of that is left, so a thing that moves again mid-flight carries the rest of the old trip into the new one: `Slides` keeps one per layer that changed rows, and one more carries the scroll. `app` ages them all on one clock, capped per frame, and ages before it starts anything new — the other way round, an animation born this frame is a third over before its first frame is drawn.

The panel is a scroll area. `Panel::band` is as much of the stack as the window has room for; `layout` takes the scroll, clamps it, and lays out only the rows the band reaches — a row it reaches part of is laid out whole and cut by `Prim::clipped`, which every card prim goes through. The band lets go of a card as it lifts — the cut opens by `LIFT_REACH` times the lift, so the lean toward the canvas is not chopped at the panel's own edge — and `free_y` clamps a carried card to the band rather than to the rows, since a row can be part shown at either edge. `Panel::bar` is the thumb, sized to the band's share of the stack. The wheel over the panel scrolls it at once; `scroll_showing` answers where the list has to be for a row to be in the band, and `app` glides there when the active layer changes — edge-triggered on the layer's id, so picking an element on the canvas brings its card into sight while scrolling away from it does not snap back. `Handle` is the panel's tab, and it stands on end: closed it is a chevron with `TITLE` under it and `KBD` on a key of its own, both written by `reading_up` — laid out flat, then put through `Prim::transformed` at `QUARTER`, a quarter turn counter-clockwise, which maps `(x, y)` to `(y, -x)`: the string's own x becomes the distance back up the tab, so the run is carried its whole measure past its top, and the height it was laid out in becomes the width it is centered across. The letters end up facing the canvas the panel comes out over. The chevron keeps its place on the header's line in both states, so toggling does not slide the arrow out from under the pointer that clicked it, and the tab gives up the key and then the word rather than run past the window's bottom edge. Open it is the chevron alone: the header behind it says the word, and a shortcut is only worth teaching for the door that is shut. The brush's settings are the window's, not a tab's, as in Photoshop; `Shift+L`, the handle beside the panel and the panel's visibility are the window's too.
- **Input flow:** `app` maps winit and gesture events to `editor` calls in screen px plus the current `View` and the document; the editor answers with a `Change` (scene, camera or selection) that `app` stores. Pan/zoom math is `View::showing` in `scene`. A stroke takes its `Tip` at the press — the pencil's constant, or the brush handed in — and release writes it into the path, so a setting changed mid-stroke does not change the ink. Selection drags transform the document live from a snapshot taken at the press; `Esc` restores it, so `cancel`/`set_tool` need the document too. What a press does is `Editor::pointer_tool`, not `active_tool`: a resize handle takes the press back from the Ctrl-is-Zoom override, and the cursor asks the same question so it cannot promise something else. Hit order over the window is strip, layers handle, layers panel, properties bar, brush palette, dock, canvas. The tablet's pen is a third source into that same funnel: `tablet` holds the axes and the tip of one hardware event until the `frame` that closes them, then hands `app` the movement before the touch — a press has to land where its own frame put the tool, not where the last one left it. `app` multiplies by the window's scale factor, since the protocol speaks surface-local logical px and the loop speaks physical, and calls the same `pointer_moved`/`pointer_pressed`/`pointer_released` the mouse does. Binding the protocol is what makes the compositor stop emulating a pointer for the pen, so the bridge owes the loop the movement as much as the touch. The axes come out of the frame first — a sample has to be taken with the pressure that arrived with it — and, unlike the movement and the touch, they are carried from frame to frame, because the protocol only sends the ones that changed. `Editor::set_stylus` is where they land: a `Stylus` is physical state like the held keys, and every mouse event puts it back to `Stylus::MOUSE`, so a pen lifted off the tablet — which reads as no pressure at all — cannot leave the mouse painting nothing.
- **Brushes.** The library is Sketchbook's own: seventeen sets and 211 brushes, converted from the `.skbrushes` files by `tools/import-skbrushes.py` into `assets/brushes/library.json` plus an icon sheet, both `include_`d into the binary. It also writes `assets/brushes/shapes.png`, the 114 nib images the brushes carry: gray + alpha, the gray full and the alpha the coverage, exactly as the glyph atlas is read, at 128 px a cell — past what the widest brush resolves, and half a megabyte for the sheet. Both of Sketchbook's kinds are on it — the 90 `shape` silhouettes 103 brushes stamp, and the 24 `texture` grains 42 wear — and the library says which a brush names. A `paperTexture` is neither: it belongs to the canvas rather than to the nib, and Sketchbook ships no image for one here. The originals are 34 MB of zip — 438 MB of shape and texture TIFFs once opened — so they stay in `.gitignore` and only what the tool writes is committed; run it again to rebuild. The importer is where the mapping lives and is documented: `size` is `maxRadius` doubled (the `metaParameter` only six legacy brushes carry is not a source), `opacity` is `maxStrokeOpacity`, `flow` is `maxOpacity`, and each `pressure` is how far the light end sits below the heavy one. Randomness is not a fraction in Sketchbook — it throws a property by an amount in that property's own unit — so those `Property::range`s are the real bands (a radius by 20, a rotation by 180°) and `Unit::Amount` writes them plainly. `Preset::face` names the nib a brush carries — a `Face::Shape`, a `Face::Grain` or `Face::Round` — and `Preset::stamp` marks the two thirds told apart by a nib or a paper of their own, so `stamp` with a `Round` face is what the engine still owes: the canvas's paper, for the 22 brushes that have nothing else. The shipped brushes are held to painting distinctly *within a shelf, among every brush but those*. `library.json` is built, not typed, but it is still read through a door — every value goes through its own `Property::set`, so an asset built wrong cannot seat a number the sliders could never reach, and one that will not parse leaves `Library::bare` rather than no window.
- A brush is Sketchbook's, not Photoshop's: `Library` holds `Set`s of named `Preset`s, one is in the hand, and an edit goes into that brush and stays there — `Preset` keeps what it shipped as, so `reset` can always take the edit back. The keyboard and the properties bar's sliders write through the same `Library::brush_mut`. `Brush` is the whole of Brush Properties, and `Property` is the vocabulary the panels read it through: label, `Section` (Pressure, Stamp, Nib, Randomness), range, get, set, the fraction along its slider and how the number is written — so no panel has to know a field's name. `Property::honored` is the one list of what the canvas actually paints with — what `Tip` carries: size, opacity, hardness, the whole `Stamp` (spacing, roundness, rotation, flow) and its `Scatter` (the randomness on size and rotation); three of Sketchbook's five randomness amounts are left out because its own sets contradict their scale — opacity and flow are thrown by five and by twenty on a property that is a fraction, and seventeen of the thirty brushes that throw the gap name an amount larger than the gap itself, so a throw either side of it would land negative more often than not — and the canvas will not guess; the rest describe a brush truthfully while the stamp engine grows into them, and nothing else may claim to know. A property's slider need not be linear: `Property::curve` bends the size's travel by a cube, since 1–700 laid out straight spends nine tenths of the track above the widths anyone draws with. The palette is Sketchbook's Brush Library, not its smaller palette: every shelf stands one under the next in one scroll, so there is nothing to pin and a brush is addressed by `(set, index)` throughout. `set_height` is the one place that says how tall a shelf stands — `layout`, the content total and `scroll_showing` all ask it, so they cannot disagree about where a shelf begins. Only the shelves the band reaches are measured; what it reaches part of is cut by `Prim::clipped`. An icon is a cell of the sheet `gfx` uploads once — raster art, the same at every scale, unlike the glyph atlas which is rebuilt per scale factor — drawn by `Prim::sprite`, a glyph prim with no tint, since the icons carry their own colors. The palette is the brush tool's own chrome: `app` builds it only with `Tool::Brush` in hand, so it comes and goes with the tool, and `Shift+B` shuts it without putting the brush down. `app` glides the list to the brush in the hand, edge-triggered on which brush it is, so taking one off a far shelf shows it while scrolling away does not snap back. `props` is the second half of that chrome: a bar under the strip carrying the name and `Property::BASIC`, and a chevron that drops the Advanced layout — the sections cut out of `Section::ALL` at `FIRST_COLUMN` into two columns, so a section added later falls into the second rather than off the bar. Closed and open never lay out the same property twice, which is why `Hit::Slider` names a field by its place and not by its property, and why `app` re-reads that place on every drag step — the bar may have folded under the pointer. A slider whose property is not `honored` is drawn in `theme.muted`: it still moves and still writes the brush, and the muting is the bar refusing to promise ink it cannot lay. The bar stands above the palette and the palette's `top` is the bar's bottom, so opening Advanced pushes the shelf down instead of covering it. A test measures every label and every range's top against the atlas, so no name in the bar is ever written with an ellipsis.
- **Stamping.** A brush does not sweep a line: it stamps a nib along one. `Tip` carries an `Option<Stamp>` — the pencil has none and goes on sweeping through `soft_polyline_prims`; every brush has one and goes through `scene::stamp_prims`, which walks the flattened screen polyline and lays a dab where the press was, then one every `spacing` of Sketchbook's own spacing units of arc length, each worth `SPACING_UNIT` — a quarter — of the nib's width. What settles that quarter is Sketchbook's own help: it names 0.1 as "a very dense brush", 10.0 as the top, and 1.2 as the **Pencil's default**. A default pencil has to draw solid, and at a quarter of a width per unit 1.2 is 30% of a diameter — where every paint program's default spacing sits, and the ink pinches to only 95% of its width between two dabs. Read as whole widths that pencil's dabs would not touch at all; read as radii it would pinch to 80%, a beaded stroke, which is not what Sketchbook ships. The walk carries its leftover across the polyline's corners, so the spacing is the stroke's and not a span's; the tail past the last dab is not stamped, as in Sketchbook, and the nib's own radius covers it. `STAMP_STEP_MIN` floors the step at a pixel, so a hair-thin brush at the tightest spacing cannot lay tens of thousands of dabs. A dab is `Prim::dab`: a box `radius` px across and `radius * roundness` down, cornered by the smaller of the two — round when they are equal, a flattened capsule when they are not, which is as close to an ellipse as the box field comes — ramped over the same `feather` a swept stroke gets and turned by the nib's own angle. What the ramp *does* over that width is `doc::Profile`, Sketchbook's four tip profiles, carried to the shader as one exponent on the coverage in `Prim.falloff` — below one the nib stays full almost to its edge, above one it fades over the whole band, and one is the plain ramp everything that is not a nib is drawn with. Sketchbook does not document its curves; its own sets do, since every brush ships an Edge to go with its profile and the two move together (airbrush never past 0.28, regularSolid to 0.75, hardSolid at 0.88 to a brush, sharp from 0.89 up), so the profile is read in the order the sets themselves put it in. The clip is never bent: a soft shadow is still cut by a hard edge. A nib is never let vanish (`NIB_MIN_PX`), however flat it is squished. Flow is what one dab lays and opacity is the ceiling the pile reaches: `stamp_prims` puts the flow in each dab's own alpha, and `Frame::stroke` groups a stamped stroke as `Blend::Build` so the dabs meet one over the next. It follows that flow joins `Tip::is_direct`'s question — a nib that does not cover on its own must build in the scratch, or it would pile onto the board itself. The pen drives it too: `doc::Pressure` on the `Stamp` is how much of the size, the opacity and the flow a lighter touch takes away — Sketchbook names the two ends of each and the amount is the gap between them — and `doc::Envelope` on the stroke is what the hand actually did, readings from end to end spaced evenly along the stroke's own length, so a reading is asked for by how far along a dab lands and a curve can answer as well as the polyline it was fitted from. `Editor::Stroke::envelope` is the one that builds it, and both the live stroke and the release go through it, so the ink does not jump when the stroke is let go of; it keeps only what the nib can read, so a brush no pressure drives and a mouse both leave it empty. Under a lighter touch a dab is narrower, thinner, and closer to the next — the gap is a share of the nib's width, so the step shrinks with it and the ink stays as solid as it was. Flow driven by pressure joins `Tip::is_direct`'s question for the same reason opacity does: a dab that does not cover has to build in the scratch. A `doc::Scatter` throws each dab off true: its radius by so many world units and its angle by so many degrees — amounts in the unit of what they throw, which is how Sketchbook states randomness. The rhythm is never thrown; the gap is one of the three amounts whose scale the assets contradict. The throw has to be the same every frame, or the ink would shimmer: `dice` is splitmix64 over `(seed, dab index, salt)`, one salt per property so the throws do not track each other, and `seed_at` draws the seed from where the stroke *began*, in world units — never from the screen, which the camera moves, and never from anything that grows, since a live stroke and the path it is fitted into must scatter alike or the ink would jump at the release. The dab count is zoom-independent by construction (the step and the arc length both scale with `px_per_world`), so a dab keeps its own throw as the board is zoomed. A nib with no scatter skips the dice entirely. `Stamp::follow` is one of Sketchbook's four Rotation Dynamics: the walk adds the heading of the span a dab lands on to the nib's own angle. It is a `bool` and not the enum because it names what the canvas does with the *stroke* — a nib either runs along it or does not. The other two the stylus drives are not the nib's business at all: `Stylus::twist` resolves the lean (and, for `TiltAndRoll`, the roll on top of it) into one angle at the moment the sample is taken, and the stroke keeps it in its envelope beside the pressure — so the document records what the hand did rather than what the brush would have asked of a hand that is no longer there.

A nib may carry art of its own, and Sketchbook has two kinds that do quite different things. A **shape** is stamped in place of the round box; a **grain** is worn over one, which keeps its edge, its ramp and its profile and is eaten into. `scene::Shapes` is what `ImageSlots` is for a board's images — the sheet's slot, how it is cut up, and which cell each nib is in by the name a stroke calls it — and `Shapes::cell` hands back a `Cell` (a uv and a slot). `scene::Art` is what the walk is then given in its `Nib`, beside the radius, the ramp and the world-to-px the scatter is thrown by: `Round`, `Shape(cell)` or `Grain(cell)`. `Prim::shaped_dab` is a `KIND_IMAGE` box over the same rect the round dab would have filled, turned the same way, with square corners and no ramp, since the shape's own alpha is the only edge; `Prim::grained_dab` is `KIND_GRAIN`, which is the round dab exactly — corner, ramp and profile — with the cell's alpha multiplied into its coverage in the shader. The grain turns with the nib because it *is* the nib's; the canvas's own paper would stand still under it, and is not this. The sheet is full gray under its coverage, so `texel * ink` is the mark, exactly as the glyph atlas works. A stroke names its nib by name and never by cell: a board outlives the sheet it was painted from, and an index would move the day a set is added — a name this build does not carry lays a plain round nib rather than nothing, so a board painted elsewhere still opens. The shape is not part of the body a slider can reach, so it lives on `Preset`, not on `Brush`: `Preset::tip` is the one that knows both halves, and `Library::tip` is what the editor is handed at the press. The nib is document data, not session state: `doc::Stamp` sits on `Path` and `Stroke`, absent on disk when the stroke was swept, and `Stamp::checked` refuses a board holding a turn of four hundred degrees or a gap of nothing — so a saved brush stroke reopens as the same ink and not as a sweep.

- **Units:** world unit = logical pixel at zoom 1; `View` folds the window scale factor in. Dock, panels, grid and selection handles are sized in logical px; brush size is world units, so it scales with zoom like the ink it makes.

# Security Invariants

Verified by tests; don't loosen them casually:

- IPC schema is closed (§5): unknown op, field, or version is an error, never best-effort. One JSON per line, frames capped at 64 KiB, socket `0600`, same uid only.
- Disk (§9.3): `~/.local/share/omawhite` and subdirs `0700`, files `0600`, writes are atomic (tmp in same dir + rename).
- Export destinations arriving over the socket or CLI are candidates; the binary validates them against the allowlist (§8.2) before writing. A path that came back from a portal dialog is not one of those — it is the user's own choice, made in a system dialog — so save/open paths are not measured against that list. Loading one changes nothing about the parse: schema closed, every blob still checked.
- An `image` element's `blob` is a bare lowercase-hex sha256 — checked when the board parses and again before it becomes a path. Pasted bytes are refused past 8192 px a side, read from the header before any texel is allocated.

# Conventions

- Documentation, code (identifiers, comments, messages), and commits in English.
- Commits are atomic — one coherent change each — with succinct messages.
