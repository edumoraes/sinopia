# Omawhite

Local-first whiteboard for Omarchy with export for the agent. Native Rust engine (winit + wgpu), single binary `omawhite`, later fronted by a thin Omarchy shell plugin. User data lives in `~/.local/share/omawhite/`; the control socket is `$XDG_RUNTIME_DIR/omawhite.sock`.

# ARCHITECTURE.md Is a Draft

[ARCHITECTURE.md](ARCHITECTURE.md) is a working draft under construction, not a contract: the real architecture emerges from development. [README.md](README.md) tracks what actually exists — read it first. `§N` references in code and docs point at ARCHITECTURE.md sections. When code and draft diverge, the code is the truth; evolve the draft as decisions actually land.

# Working Style

Scaffolding means minimum: build in small slices, don't implement the whole draft ahead of need. §15 of the draft orders the implementation cuts to de-risk the stack — stay inside the slice at hand.

# Commands

```sh
cargo build
cargo test                    # full suite
cargo test store::            # one module's tests (inline #[cfg(test)] modules)
cargo run                     # most recent board, or a new one
cargo run -- --new            # new board
```

The agent-facing verbs need a live instance and answer one line of JSON:

```sh
omawhite agent frames                     # the frames of the open board
omawhite agent read <frame> [--to DIR]    # export one, by id or by name
omawhite agent add <fragment.json>        # graft a frame onto the board
```

Save, open and the unsaved-work question go through `xdg-desktop-portal`
(any backend with a file chooser; `-gtk` here). The question itself has
no portal and falls back to `zenity`; without it the answer comes back
as a cancel, so nothing is lost.

Headless-ish smoke test (opens a window, renders 3 frames, exits):

```sh
XDG_DATA_HOME=/tmp/omawhite-smoke cargo run -- --socket /tmp/omawhite-smoke.sock --smoke-frames 3
```

# Architecture

Module layout is in the README. The shape that matters:

- **Single instance.** `main.rs` maps CLI flags to an IPC request; if the socket answers, the intent is forwarded and the process exits — only otherwise does it become the main instance and start the winit loop. `--export`, `--shutdown` and `--theme` never spawn a window.
- **Pure core, thin shell.** `doc` (serde data, versioned schema, layers and paint order), `scene` (view + document → SDF prims, frames, the affine that carries a prim, groups and the passes that composite them), `geom` (affine maps, oriented frames), `select` (element frames, hit-testing, handles and the transforms they drive), `bitmap` (image bytes → RGBA8, paste size), `grid`, `theme`, `omarchy` (the desktop's own look, parsed), `brush` (the library of sets and presets, a brush's body and the properties that address it, the tip a stroke carries, the pointer's ring), `editor` (tool, held keys, stroke and its tip, pan/zoom gesture, selection and the drag reshaping it, the active layer), `dock` (the tools, and after a divider the inks a stroke can be laid in), `slots` (the brush strip on the left: the brush in the hand, the two buttons, the ten seats), `palette` (the brush library beside it: the shelves, the grid of icons, the scroll), `props` (the brush properties bar and the Advanced layout it drops), `layers` (the panel on the right, its scroll area, and the handle that opens it), `tabs` (the strip, and what a tab gives up when it narrows), `text` (glyph atlas, measure, layout, truncation), `project` (a document's origin and dirty flag), `history` (the states a board came to rest in, and the spot the hand was on at each), `store` (XDG persistence, blobs, project files), `export` (what leaves the board: the scope, its box, its sub-document, the frames it lists, the fit a picture of it is taken at), `graft` (what comes back: the fragment, the ids minted anew, the free spot), `field` (an editable value, one line or several: the caret, the selection, the keys that move them, the lines a box shows it in), `send` (the export dialog: the rows, the folder, the instruction's box, the skills menu, the picture at its foot), `agents` (the agents running here, parsed out of herdr, tmux and `/proc`, and what reaching one types and pastes), `skills` (where each harness keeps its skills, which may be called, and how a call is written), `cli`, and `ipc` are pure and carry the whole test suite. `app` (winit event loop, input routing, socket → event-loop bridge), `gestures` (Wayland `zwp_pointer_gestures_v1` → event-loop bridge), `tablet` (`zwp_tablet_v2` → event-loop bridge, save the frame it accumulates, which is pure and tested), `clipboard` (`wl_data_device` → event-loop bridge, both ways), `dialogs` (portal file chooser and message box → event-loop bridge) and `gfx` (the instanced SDF pipelines, image textures, the scratch texture) are the untested shell — keep logic out of them so it stays testable.
- **Frame data flow:** grid + document + live stroke + selection overlay + brush ring + dock + brush strip + brush library + properties bar + layers panel + tab strip → `scene`/`select`/`brush`/`slots`/`palette`/`props`/`layers`/`tabs` prims, gathered in a `scene::Frame`. An image is one prim too: `scene` needs the renderer's blob → texture-slot map to emit it, and `gfx` cuts the frame into runs wherever that slot changes. A glyph is that same textured box with `Prim.uv` naming its cell of the atlas; the atlas is white with alpha for coverage, so `texel * color` is the ink. It has its own slot in `gfx`, never an entry in the blob map. A soft or translucent stroke is a **group** in the frame: `scene::passes` plans, on the CPU where it is tested, a wipe and a draw of its prims into a window-sized scratch texture and one composite box laid back at the stroke's opacity, dropping groups off the viewport; `gfx` only executes the passes. How the prims meet in the scratch is the group's `blend`: `Union` is every channel a max, premultiplied — the union of their coverage, what a swept stroke needs so a soft edge does not bead at its joints — and `Build` is one over the next, what a stamped stroke needs so its dabs pile up. How the finished shape meets what it is laid on is the group's `lands`: `Over`, or `Erase` for a stroke that takes ink away. A crisp opaque stroke — every pencil stroke — never becomes a group.

There is a second surface, the **sheet**, and it is what makes an eraser possible: a raster layer is pixels, and an eraser rubs out that layer and nothing under it. `Frame::sheet` wraps a `Paint` whose strokes include one that erases — and only then, so a paint with nothing to rub out is drawn exactly as it was before — and the pass plan opens the sheet with a wipe, draws or composites every stroke of that paint onto it (an eraser's group laid with `Erase`, which is a plain destination-out), and lays the whole sheet on the window once at full strength, since each stroke's own opacity was spent on the way in. A `Pass` is therefore one shape for all three surfaces: what it draws `Onto` (`Window`, `Sheet`, `Scratch`), the box it wipes first, the `Lay` it puts down before anything else and how that meets what is there, and the prims it then draws. The window's first pass is what clears it, so there is always one; every other surface loads, since a wipe box is what opens the part of it being used. The scratch and the sheet each have a texture slot of their own, like the atlas.

The stroke in progress is painted **inside the document's own frame**, on the layer it is going to land on (`Editor::live_layer`, handed to `document_prims` as a `Live`): that is where it meets the ink already there the way it will at the release, and the only place an eraser has anything to rub. A stroke whose layer holds no paint yet is drawn last, over everything, as it always was — and an eraser there paints nothing at all, which is exactly what it will do when it lands.
- **Documents and tabs.** One tab is a `Project` (document + `Origin` + dirty flag) and the `Editor` driving it: tool, selection and any drag belong to a document, so a tab switch hands nothing on and only re-applies the held modifiers, which are physical. `Origin` decides where `Ctrl+S` writes — `Board(id)` for a **draft**, the kind the store keeps, `File(path)` for a project the user named, `Untitled` until it has been drawn on. A draft keeps itself: `App::touch` sets a debt that the next change pushes back, and `about_to_wait` pays it once the hand has been still for `SAFETY_DELAY` — `ControlFlow::WaitUntil`, since a loop sleeping in `Wait` would never wake for a deadline of its own, and a debounce because `Change::Scene` fires on every sample of a stroke and saving on the change itself would write through the middle of a gesture. `keep_drafts` is also what materialises an `Untitled`: nothing is written for a new board until it is drawn on, which is what keeps every `+` from leaving an empty one in the recents. What a draft earns, a named file does not — writing into it behind the user's back would empty `Ctrl+S`, the dot on the tab and the question at closing time of all their meaning, so a dirty draft is kept on the way out and only a dirty file is asked about (`owes_an_answer`). `index.json` is still the only file the plugin reads, and it is now a list of **recent projects**: an entry carries an optional `path`, absent for a draft the way a raster layer's kind is absent, so an index written before recents existed still opens meaning what it meant. Identity is the id *or* the path, so a draft saved under a name stops being two entries and one file stays one entry whatever wrote it; saving a file calls `Store::remember_file`, which keeps the path and never a copy. Opening one needs `op: open_file` / `--open-file` rather than a second shape of `open`: the schema is closed, and guessing whether a string is an id or a path is the best-effort §5 forbids — the path must be absolute and free of `..`, which is a shape check and not the export allowlist (§8.2), since that one guards destinations. Reaching for a file that has gone is what proves it gone, and the only thing that drops an entry: a project on an unmounted drive keeps its place. `open` is never empty — the last tab closing sets `closing` instead, because every accessor assumes a tab in front.
- **Undo.** A tab's `History` is the states its board came to **rest** in. `Change::Scene` fires on every sample of a stroke and on every step of a drag, so the step is the rest, not the change: `App::remember` is what decides, and `App::settled` is the test — the editor holding no gesture (`Editor::busy`: a stroke, an area, a navigation or a drag, which is wider than the `is_moving` that only ever meant a `Drag::Move` past the click slop) *and* no layer card in the pointer's hand, since a carried card lives on `App` and reorders the document on every move while the editor sits perfectly still. That card is also why `pointer_released` and `focus_lost` call `remember` themselves: both let go of it behind an early return, and the canvas never saw the press, so no `Change` comes back to end the gesture the way a release on the canvas does — without it a drag across two rows is applied and never written down, and the next change to come to rest would swallow it into one step. An entry is the whole `Document` plus the editor's `Spot` — selection, ink layer, frame being worked in — kept together so neither has to be checked against the other: a spot restored beside the document it was taken with names ids that document has, **by construction**, which is why undoing a delete brings the objects back selected and why there is no reconciliation pass to get wrong. The top of the past *is* the present, and `History::mark` keeps its spot live whether or not the board is at rest — a press on an object selects it *and* starts dragging it in one motion, so a spot written only at rest would still be the empty one the tab was born with, and undoing the move would put the object back and drop it. `History::keep` marks and returns when the board is what it already was, which is also why `Esc` restoring a drag pushes nothing. The camera is in the document and deliberately out of a step, at both ends: `Document::same_board` destructures rather than lists its fields, so a field added later cannot slip past undeclared, and `Entry::restore` keeps the camera the live document has — panning is not work, and a step back that moved the view would make the two mean the same thing. A snapshot rather than an edit that knows its own inverse: it cannot come to disagree with the model because it *is* the model, so every operation is undoable the day it lands without a line at its call site. The price is memory — an entry carries the whole board, so the cost of a step climbs with the session — and the ceiling that pays it is a depth *and* a byte budget, the oldest dropped first and the present never, so a heavy board gets fewer steps. `trim` counts only the past, and says why: it runs at the end of `keep`, which has just dropped the future, and undo moves an entry between the two without changing the total. `Vec<Arc<Element>>` would buy the depth back if a real board ever makes it hurt, and the interface does not change if it lands. The panel needs nothing: `Slides::restack` compares the stack against the one it last saw, so undoing a reorder animates the cards home on its own.
- **Layers.** `Document.layers` is bottom to top and never empty in memory; every element names its layer by id, and `from_json` settles both — a board without layers gets `Layer 1` and its elements join it, an unknown or duplicate id is an error. Paint order is `Document::painted()`: the layers' order, then document order within a layer, hidden layers skipped — `scene` paints through it and `select` hits through it, so the renderer and the pointer never disagree on what is on top. A layer also says what it holds: `Kind::Raster` accumulates, `Kind::Vector` is the one object it was made for. Raster is the default and absent on disk, so a board written before kinds existed opens meaning what it always meant. The active layer is session state on the `Editor`, kept as an id (it survives reorders) and resolved to the top when unset or gone, and picking an element makes its layer active. Where new ink lands is `Editor::ink_layer`: raster joins the active layer when that one takes pixels and opens one above it when it does not (a brush stroke over a vector layer), vector always opens one of its own — so every pencil stroke becomes a layer, and every brush stroke joins the sheet it is painting on. `fresh_layer` is the half that opens and activates; a pasted image calls it directly, since a paste never joins what is already there. What a raster layer accumulates is one element: `Element::Paint` holds a `Vec<Stroke>`, and a brush release pushes onto the paint already on that layer, opening one only when there is none. A `Stroke` is a `path` without an identity — the curves and the ink they were laid with — because the ink belongs to the stroke, not to the object: changing brush mid-painting must not repaint what is already down, and two strokes cannot share one `path`, whose curves are a single chain (`path_prims` would draw the jump between them). `scene` paints and composites a paint stroke by stroke, so painting twice over the same place darkens it as pixels would; `select` frames it around every stroke (`ink_frame`), hits it on any (`ink_hit`) and transforms them all together. A layer and its object go together in both directions: `delete_selection` drops the layers its deletion empties, and `Editor::remove_layer` on the last layer — which always stays — clears what is on it instead of refusing. The kind a stroke asks for is the tool's, read at the release: switching tools cancels the stroke in progress, so it is still the tool that started it. The panel's `+` makes a raster layer, and each card marks what its layer holds — `Row::mark` at the end opposite the eye, a pixel grid or a curve, drawn in `theme.muted` because it is read, never clicked. Layer operations live on `Document` (add above, remove but never the last, move one step, reorder to any index); the editor wraps them and keeps the selection honest (what is hidden or removed leaves it). Dragging a row is `reorder_layer` on the active layer, applied live on every move: the press selects the layer, `Panel::drop_index` names the row under the pointer — a purely positional answer, so the reorder it causes cannot make it oscillate — and `app` holds nothing but the flag saying the pointer is still down. A row paints as a card inside it (the rect is the hit target, the card less the gap between two of them is what is drawn). `Panel::prims` takes a `Lift { index, y, t }`: the card it names is built in its row like any other, then every property is carried `ease(t)` of the way — a longer shadow, an outline mixing to `theme.lifted` (a fixed blue, the one color not derived from the plugin's three), and finally `Prim::transformed` over the card's own prims, contents and all, growing it, turning it clockwise, leaning it toward the canvas and putting it at `y`. It is painted last, over the cards it is passing. `y` is the pointer less the grip the press took, clamped to the rows on show, so the card follows the pointer instead of stepping between rows. Only the clock is `app`'s: `Carry` walks `t` toward whether the button is down, asks for the next frame while it moves, and outlives the release so the card eases back into its row. Everything else the panel eases is a `Coming` — how far it still has to come and how much of that is left, so a thing that moves again mid-flight carries the rest of the old trip into the new one: `Slides` keeps one per layer that changed rows, and one more carries the scroll. `app` ages them all on one clock, capped per frame, and ages before it starts anything new — the other way round, an animation born this frame is a third over before its first frame is drawn.

The panel is a scroll area. `Panel::band` is as much of the stack as the window has room for; `layout` takes the scroll, clamps it, and lays out only the rows the band reaches — a row it reaches part of is laid out whole and cut by `Prim::clipped`, which every card prim goes through. The band lets go of a card as it lifts — the cut opens by `LIFT_REACH` times the lift, so the lean toward the canvas is not chopped at the panel's own edge — and `free_y` clamps a carried card to the band rather than to the rows, since a row can be part shown at either edge. `Panel::bar` is the thumb, sized to the band's share of the stack. The wheel over the panel scrolls it at once; `scroll_showing` answers where the list has to be for a row to be in the band, and `app` glides there when the active layer changes — edge-triggered on the layer's id, so picking an element on the canvas brings its card into sight while scrolling away from it does not snap back. `Handle` is the panel's tab, and it stands on end: closed it is a chevron with `TITLE` under it and `KBD` on a key of its own, both written by `reading_up` — laid out flat, then put through `Prim::transformed` at `QUARTER`, a quarter turn counter-clockwise, which maps `(x, y)` to `(y, -x)`: the string's own x becomes the distance back up the tab, so the run is carried its whole measure past its top, and the height it was laid out in becomes the width it is centered across. The letters end up facing the canvas the panel comes out over. The chevron keeps its place on the header's line in both states, so toggling does not slide the arrow out from under the pointer that clicked it, and the tab gives up the key and then the word rather than run past the window's bottom edge. Open it is the chevron alone: the header behind it says the word, and a shortcut is only worth teaching for the door that is shut. The brush's settings are the window's, not a tab's, as in Photoshop; `Shift+L`, the handle beside the panel and the panel's visibility are the window's too.
- **Frames.** A frame is an area that holds objects, with a stack of its own, and it is itself a layer — of `Kind::Frame` — on the board's stack. It is an `Element::Frame` on that layer, which keeps the invariant the rest of the model rests on: *a layer is the object it holds*. `Document.elements` stays flat and an object inside a frame names one of that frame's own layers; layer ids are unique across the whole document, so the `layer` an element already carries says where it is and nothing else has to. `settle_layers` checks both stacks: a frame layer and its frame are one thing neither half stands without, a frame's stack is never empty (it gets `Layer 1`, exactly as the board does), and a frame inside a frame is refused — frames do not nest in this cut. `Document::stack(frame)`, `locate`, `frame_at` and `rehome_layer` are how two stacks are addressed, and every layer operation takes the frame whose stack it acts on, so an index is never read against the wrong one.

`Document::painted()` is the seam that carries the feature: it yields a `Painted { index, element, within }`, and `within` is the frame whose boundary cuts that element. `scene` reads it for the clip and `select` reads it for the hit test, so the renderer and the pointer cannot come to disagree about what is cut away — ink that is not drawn is not there to be clicked or marqueed either. A frame layer paints its frame first, then that frame's own stack, so what is inside an area is painted over it and under whatever comes next, and hiding a frame layer takes everything in it. `index` is still into the flat `elements`, which is what keeps `select` answering with ids. The cut is `Prim.clip`, an axis-aligned box already in the shader, applied by `scene::cut_all` before `Frame::stroke` and `Frame::sheet` so a grouped stroke carries it into the scratch; `painted_bounds` honours it, so a stroke mostly outside a frame does not make the compositor pay for ink nobody sees. That the cut is axis-aligned is exactly why **a frame does not turn**: `select::transform` maps its box and drops the turn, and the editor does not offer the rotation rings while a frame is selected, so the cursor cannot promise a turn that will not happen.

Membership is geometric, and decided at two moments. New ink: the frame the **press** landed in is written on the stroke (`Stroke::born`) and read for the rest of it — the ink is painted from its first sample, so re-reading the geometry at the release could cut a stroke by one boundary and land it under another, which is the same reason the tip is taken at the press. A stroke that wanders out of the frame it started in belongs to that frame. Existing objects: the **release of a move** asks each moved object's centre which area holds it, and `rehome_layer` moves its *layer* to that stack — the layer moves because a layer holds one object and the two go together, so the element goes on naming its layer and nothing about it changes. A frame never rehomes. Moving a frame carries what it holds (`move_snapshot` is the selection plus every element on a selected frame's layers); resizing moves the boundary alone. A frame drawn over things claims them, on the same centre rule: an object visibly inside an area, uncut, would contradict the boundary the moment it appeared. The Frame tool (`F`) drags the area out, refusing a drag under `MIN_FRAME_PX` — a click is not an area, and the floor is in screen px because what it refuses is a hand that did not mean to drag. `Editor::inside` is the frame being worked in, session state like the selection, read through `inside_in(doc)` so a deleted frame cannot leave the editor pointing into it; picking an element goes to its stack as well as its layer. The background is the theme's surface at birth (`Theme::panel_hex`, handed over by `app` so the editor never sees a `Theme`) and an ink picked with a frame selected repaints it. The panel goes on showing one flat stack — whichever the editor stands in — so its lift, its slides, its scroll and its thumb never learn frames exist; a frame's card ends in the chevron that goes into it, in the mark's own place and in `theme.icon` rather than `theme.muted`, because a mark is read and a chevron is pressed, and inside a frame the header says the frame's name and that title is the way back out.

- **The door an agent asks through.** Export to the agent goes one way — a person presses `Ctrl+E` and a page lands where an agent is running. `omawhite agent …` is the way back, and a **frame** is the unit in both directions: the only thing on a board that is named, bounded and addressed, where the whole board is unbounded and a loose selection has no name. `agent frames` lists them (`export::frames`: id, the layer's name, the box, and what `painted()` says the boundary cuts, so a listing cannot disagree with a picture); `agent read <frame> --to <dir>` is `Scope::Frame` through the very path `Ctrl+E` walks — `App::write_page`, lifted out of `send_to` so both doors are one — landing the same `docs/boards/<slug>/board.{png,json,md}` under the same §8.2 allowlist. **The read goes through the listing**, so a frame on a layer the person hid is refused rather than exported as a blank page: what an agent can see and what it can take have to be one answer. The slug falls back to the id where a name slugs away to nothing — every non-Latin name does, since a slug is ASCII, and two of them sharing the word `board` would write their pages over each other. And **the picture is the sub-document**, not the board seen through its box: the json beside it is the scope, and drawing the whole board put a neighbour's ink in the `EXPORT_MARGIN` of a picture whose json said nothing about it. `agent add <file>` grafts a frame **onto** the board. An agent cannot draw into a frame that exists, delete, move or switch tabs: one frame in, one frame out, and the board stays the person's.

The three are ops of their own on the closed schema (`frames`, `read_frame`, `add_frame`), and what makes them unlike every op before them is that **their answer is the work**: a listing wants the live document and a picture wants the GPU, and both are the event loop's. So the socket thread does not ack and forget — `UserEvent::Ask(req, Sender<Event>)` hands the request across and waits on the channel, and a loop that is gone or an `ASK_TIMEOUT` that passes comes back as a `denied` the caller can read rather than a socket dying under it. The two are told apart, and the timeout says the work may still have landed, because `add_frame` is not idempotent and an agent reading a flat "no" plants the frame twice. That waiting is also why the server takes **a thread to a connection**: an ordinary op gives itself two seconds, and single file it simply failed for the length of a graft or a render; the client gives those three a longer deadline than the loop's own, so what an agent gets is the reason and not a timeout. `read_frame` takes an **id**, never a name — resolving a name is two round trips in the CLI, outside the schema, for the same reason `open` and `open_file` are two ops, and an ambiguous name is refused naming both ids. `add_frame` takes a **path**, never the content: §5 says the socket speaks intent and never scene content, and a frame with ink in it would not fit 64 KiB. An answer that would not fit is `denied` naming the cap (`proto::fits`), applied once where the bytes go out rather than at each place an answer is built, because a listing cut short in silence would be a lie about the board. What an agent hands over is read through `store::read_capped`: the open handle answers rather than the path, `O_NONBLOCK` because opening a FIFO is itself what blocks, and the cap is on the read because a character device reports no length at all.

`graft` is the pure half. **The fragment is what `read` writes** — one frame plus what stands on that frame's own layers, exactly `export::sub_document` of a `Scope::Frame` — so one shape serves both directions and `from_json` + `settle_layers` are the whole of the validation. Both halves read `elements` rather than `painted()`, so **a hidden layer travels hidden in either direction** rather than being dropped: a person who put a layer away still owns what is on it, and a read that quietly left it behind would delete that work on the round trip. It mints every id anew — the id and nothing else, so a frame staged hidden arrives hidden — and handing back the page just read plants a sibling rather than writing over the frame it came from; and **the board picks the spot**, to the right of everything and aligned with its top, because an agent cannot see the board — the fragment's `w`/`h` are the agent's and its `x`/`y` are not read. The move is an `Affine::translate` through `select::transform`, which already knows how to carry every kind of element, a frame included; `graft::placed` checks the result, since the board's spot is *added* to the agent's coordinates and a fragment far enough out overflows to infinity — which `to_json` writes as `null`, leaving a draft the autosave keeps and nothing ever opens again. `plant` is `planned` then `apply` so that everything which can refuse a fragment runs before its images are committed: a graft turned down after that would leave bytes in the store that nothing on the board names, and the store has no way to collect them. Images close the circle: `app` resolves each blob before the graft — in the store already, or the bytes in `blobs/` beside the json, name-checked before the string is ever a path, hashed against the name they arrived under and put through `bitmap::decode` for the 8192 px ceiling — and then `load_images`, the same door a reopened board goes through, because bytes in the store are not a texture and an image nobody uploaded paints a placeholder for as long as the board is open. The graft is a `Change::Scene` like any other, so it is one undo step and a draft owes the disk a save for it.

What an agent can draw is what the canvas already draws: rects, ink paths, images. **`Rect.text` is in the schema and nothing renders it**, so a label today is a picture the agent rendered — and drawing that text is the next slice, the one that would make a diagram written by an agent read itself. `read_frame.dir` is a destination and takes the allowlist; `add_frame.path` is a *source*, absolute and free of `..` as `open_file` is, and deliberately not measured against a list that guards where bytes are written. §9.4 holds both ways: what an agent reads is quoted under the preface saying it is an inventory and not an order, and what it writes is geometry through a closed schema. The skill that teaches all of it is `skills/omawhite/SKILL.md`, one file with frontmatter plus an installer.
- **The export dialog.** `Ctrl+E` opens it on what is selected, and it is modal for every input — presses, keys and the wheel alike; a press outside it closes it. It is `dock`'s shape (layout, hit, prims) and holds no state: `App::send_panel` lays it out once a frame together with the lines the instruction wraps to, since how many there are is what decides its height, and every door onto the dialog — drawing, pressing, the wheel, the cursor — asks through that one function. It stands 640 logical px wide, never closer to the window's edge than a margin. A row is the agent's maker's mark (a cell of `assets/agents/logos.png`, a sheet built by `tools/agent-logos.sh` from the vendors' own marks and uploaded once like the dock's icons; an agent herdr knows and this build does not gets its initial on a tile), its name as its makers write it (`Agent::name`), the last directory of where it works — and one more above it for as long as two different places would otherwise read alike (`agents::folders`) — and at the far end what herdr says it is doing.

  The instruction is a `Field::lines`: `Shift+Enter` breaks a line and Enter sends. It wraps at `Panel::text_width` — short of the scrollbar whether or not it is showing, so no line rewraps the moment the box starts to scroll — after the last space that fits, or between two characters of a word wider than the box (`Atlas::wrap`); the box grows a line at a time to `MAX_LINES` and then scrolls, and a window too short shows fewer, since a dialog run off the bottom would hide the rows it is for. The arrows and Home and End walk the lines as the box shows them (`Field::up`, `down`, `line_home`, `line_end`), keeping to one x; `field::follow` keeps the caret's line in sight, the wheel over the box moves the lines, and a thumb says where they are. A press places the caret (`Boxed::at`, `Field::index_at`), Shift carries the selection there, and a drag selects, running on into lines scrolled away. Every field has a selection (`Field::anchor`) that Shift, Ctrl+A and the pointer make and that typing spends, and `edit` is the one mapping of keys onto a field — the dialog's two and a layer's rename alike. Only there do held keys repeat. The clipboard's keys come before either field's: `Ctrl+V` asks for text (UTF-8 by its MIME name first) and lands it in whichever field still has the keyboard, cleaned for it by `field::clean` — a line's breaks run on in a field of one line, a tab is its spaces, anything else unprintable is dropped — and never past the field's limit, which for the instruction is the send's own `PROMPT_MAX`. `Ctrl+C` and `Ctrl+X` make the board the selection's owner through a `wl_data_source`; a selection is set in answer to an input event by its serial, and winit keeps its serials to itself, so the clipboard's own queue holds a keyboard and a pointer on the seat that it listens to for nothing but the last serial each was handed.

  **Skills.** Typing the target's mark opens a menu of its harness's skills, filtered as the name is typed (`skills::token`, `skills::matching`): `/` first in the message for Claude Code, OpenCode and Gemini CLI, `$` at the start of any word for Codex, `/` again for Crush — whose skills are called through its model and so are taken as the words "Use the <name> skill." (`Call::Words`). `skills::harness` is where each one's folders and naming are written down, read off each harness's own source: Claude Code names a skill by its folder and brings the skills of the plugins switched on for the person as `plugin:skill`; the others name it by its frontmatter. The target's skills are read when it becomes the target (`Sending::aim`), from the head of each `SKILL.md` and never past 64 KiB of it, through the same non-blocking open a capped read uses. A skill the person may not call is not offered, and neither is a name `skills::callable` refuses. **A call reaches Claude Code typed**: a paste of more than three lines is a placeholder there, and a slash inside one is text — measured against Claude Code 2.1.280 in tmux, the whole prompt pasted drew a reply about the diagram and the probe skill never ran, while the call typed and the rest pasted ran it. `agents::typed_call` splits the call a prompt opens with off the rest for a harness whose `typed` says so, and `agents::send` types it (`herdr pane send-text`, `tmux send-keys -l`) before pasting the rest as it always did. tmux waits `SUBMIT_AFTER` before its Enter, as herdr does, since Gemini CLI takes an Enter within 40 ms of a paste for a newline in it.

  **The picture.** The foot of the dialog is what leaves: `App::ensure_picture`, run before a frame is built as the atlas is, takes the scope's sub-document through `App::render_sub` — the very path `board.png` is drawn through, so the two cannot differ — fitted into the foot (`export::fit_view`, at no more than `PICTURE_CEILING` px a world unit) at the size in px it is shown at, uploads it into a slot of its own replaced in place, and takes it again whenever that size changes. The layout knows its shape before it exists (`export::shape`): as wide as the dialog for a wide scope, no taller than 160 px for a tall one, and in a short window it gives up height before the box gives up its last line — and goes, once too small to read.
- **Input flow:** `app` maps winit and gesture events to `editor` calls in screen px plus the current `View` and the document; the editor answers with a `Change` (scene, camera or selection) that `app` stores. Pan/zoom math is `View::showing` in `scene`. A stroke takes its `Tip` at the press — the pencil's constant, or the brush handed in — and release writes it into the path, so a setting changed mid-stroke does not change the ink. What the release writes down is `Editor::laid_curves`, and the two tools part ways there. Both drop the jitter under `FIT_TOLERANCE_PX` first — what sits within a pixel of its own chord is the digitiser's, not the hand's. A pencil line is then fitted with cubics (`curve::fit`), because a vector object *is* its curves: they are what a resize scales and what an editor would take hold of. Paint is pixels and owes nothing but the path the hand took, so a brush keeps that path leg by leg (`curve::polyline`, one cubic a segment with its handles at the thirds, which is that segment exactly). Fitting reads a curve into the samples, and a fast stroke leaves too few, too far apart, for there to be one: the exit tangent comes off the last two of them and carries a handle as long as the span, so the ink hooked the other way at the end of a stroke the hand only ever turned one way — measured on a real one, the last cubic's control polygon turned +40.6° and then -17.7°, and the committed ink sat 2.9 world units off the line drawn, at a tolerance of 1. The polyline is also what the stroke was already being painted as while it was live, so the ink no longer shifts under the pointer at the release. Junction points repeat between consecutive cubics; both walks skip a span of no length, so they cost nothing. Selection drags transform the document live from a snapshot taken at the press; `Esc` restores it, so `cancel`/`set_tool` need the document too. What a press does is `Editor::pointer_tool`, not `active_tool`: a resize handle takes the press back from the Ctrl-is-Zoom override, and the cursor asks the same question so it cannot promise something else. Hit order over the window is tab strip, layers handle, layers panel, properties bar, brush strip, brush library, dock, canvas. The tablet's pen is a third source into that same funnel: `tablet` holds the axes and the tip of one hardware event until the `frame` that closes them, then hands `app` the movement before the touch — a press has to land where its own frame put the tool, not where the last one left it. `app` multiplies by the window's scale factor, since the protocol speaks surface-local logical px and the loop speaks physical, and calls the same `pointer_moved`/`pointer_pressed`/`pointer_released` the mouse does. Binding the protocol is what makes the compositor stop emulating a pointer for the pen, so the bridge owes the loop the movement as much as the touch. The axes come out of the frame first — a sample has to be taken with the pressure that arrived with it — and, unlike the movement and the touch, they are carried from frame to frame, because the protocol only sends the ones that changed. `Editor::set_stylus` is where they land: a `Stylus` is physical state like the held keys, and every mouse event puts it back to `Stylus::MOUSE`, so a pen lifted off the tablet — which reads as no pressure at all — cannot leave the mouse painting nothing.
- **Brushes.** The library is Sketchbook's own: seventeen sets and 211 brushes, converted from the `.skbrushes` files by `tools/import-skbrushes.py` into `assets/brushes/library.json` plus an icon sheet, both `include_`d into the binary. It also writes `assets/brushes/shapes.png`, the 114 nib images and the 32 papers: gray + alpha, the gray full and the alpha the coverage, exactly as the glyph atlas is read — the nibs at 128 px a cell, past what the widest brush resolves, then the papers under them in a band of their own at 192. An image says its coverage in one of two places and the sets use both: one drawn white on opaque black says it in its gray, one drawn on transparency says it in its alpha, and the colour left there is whatever it was drawn in — black, for thirteen of the nibs, which reading the gray took for empty. `OPAQUE` tells the two apart, and nothing lies between them: every TIFF the sets ship is opaque to within a hair or plainly transparent. All three of Sketchbook's kinds are on the sheet — the 90 `shape` silhouettes 103 brushes stamp, the 24 `texture` grains 42 wear, and the 30 `paperTexture` images 49 are dragged over — and the library says which a brush names. The originals are 34 MB of zip — 438 MB of shape and texture TIFFs once opened — so they stay in `.gitignore` and only what the tool writes is committed; run it again to rebuild. The importer is where the mapping lives and is documented: `size` is `maxRadius` doubled (the `metaParameter` only six legacy brushes carry is not a source), `opacity` is `maxStrokeOpacity`, `flow` is `maxOpacity`, and each `pressure` is how far the light end sits below the heavy one. Randomness is not a fraction in Sketchbook — it throws a property by an amount in that property's own unit — so those `Property::range`s are the real bands (a radius by 20, a rotation by 180°) and `Unit::Amount` writes them plainly. `Preset::face` names the nib a brush carries — a `Face::Shape`, a `Face::Grain` or `Face::Round` — and `Preset::paper` the paper it is dragged over, which is a separate question: thirty brushes carry both. The importer is also where the things read and deliberately *not* carried are written down with their reasons — `hardnessEdge`, `tiltFactor`, `metaParameter`, and a paper's brightness and contrast — so that nobody derives them twice; `stampBlendStyle="glowBrush"` is carried but unpainted, and it is the one of the six that wants no other engine, only a board that is not white. The shipped brushes are held to painting distinctly *within a shelf, among every brush but those*. `library.json` is built, not typed, but it is still read through a door — every value goes through its own `Property::set`, so an asset built wrong cannot seat a number the sliders could never reach, and one that will not parse leaves `Library::bare` rather than no window.
- **Seats.** The strip keeps ten brushes within reach: nine numbered `1`–`9`, shipped as the first of Basic, and slot 0, which nobody fills. A seat names its brush by `(set, name)` and never by index, for the reason `Edits` already gives — a set added to `brushes/` moves every index after it, and a file written last week would then seat the wrong brush. Slot 0 is **computed, not assigned**: `Library::select` writes into it whatever was taken up that none of the nine already holds, `assign_slot` clears it when that brush is given a number, and a drop on it is refused — a seat that follows the hand cannot also be aimed at. `Edits.slots` is absent on disk while the seats are what shipped, the way a raster layer's kind is absent, so a `brushes.json` written before seats existed opens meaning what it meant; a name this build no longer carries leaves its seat empty rather than refusing the file. `Shift`+digit takes a seat and the bare digits keep the opacity they always had — the digit is read off winit's `key_without_modifiers()`, because `Shift+1` is a different character on every layout but the `1` key on all of them. The library opens from the strip's chevron and stands beside it with canvas between: both have to be on show at once, since that is what a brush is dragged across, and hiding the strip hides the library it opened.
- A brush is Sketchbook's, not Photoshop's: `Library` holds `Set`s of named `Preset`s, one is in the hand, and an edit goes into that brush and stays there — `Preset` keeps what it shipped as, so `reset` can always take the edit back. It outlives the process too: `Library::edits` is what the person changed and nothing else — the brushes off their factory settings, and the one in the hand, addressed by name and never by index, since a set added to `brushes/` moves every index after it. `store` keeps them in `brushes.json` beside the boards, on the same terms (0600, atomic), and `Library::apply` dresses the shipped sets in them at startup, passing over a name this build no longer carries and putting every value through its own `Property::set`, exactly as `library.json` is read. `app` writes them when the gesture that changed them ends — never while a slider is still moving — and once more on the way out. The keyboard and the properties bar's sliders write through the same `Library::brush_mut`. `Brush` is the whole of Brush Properties, and `Property` is the vocabulary the panels read it through: label, `Section` (Pressure, Stamp, Nib, Randomness, Paint), range, get, set, the fraction along its slider and how the number is written — so no panel has to know a field's name. `Property::honored` is the one list of what the canvas actually paints with — what `Tip` carries: size, opacity, hardness, the whole `Stamp` (spacing, roundness, rotation, flow), its `Scatter` (the randomness on size and rotation) and the depth its paper bites by; Depth is honored the way Rotation is, in that the canvas answers to it and whether a given brush shows a difference is the brush's own business — a nib naming no paper is no more moved by Depth than a round one is by Rotation; three of Sketchbook's five randomness amounts are left out because its own sets contradict their scale — opacity and flow are thrown by five and by twenty on a property that is a fraction, and seventeen of the thirty brushes that throw the gap name an amount larger than the gap itself, so a throw either side of it would land negative more often than not — and the canvas will not guess; and the whole of `Section::Paint` — Strength, Blending and Dilution, which is what the Smudge and Colorless shelves are made of — because those say what a dab does with the paint *under* it, and every stroke here is redrawn from its curves each frame: there is nothing to read back. Smearing needs a raster layer kept as pixels, and a board is infinite and pans, so keeping one means tiles in world space and an invalidation story — a different engine, not a missing line. The rest describe a brush truthfully while the stamp engine grows into them, and nothing else may claim to know. A property's slider need not be linear: `Property::curve` bends the size's travel by a cube, since 1–700 laid out straight spends nine tenths of the track above the widths anyone draws with. The palette is Sketchbook's Brush Library, not its smaller palette: every shelf stands one under the next in one scroll, so there is nothing to pin and a brush is addressed by `(set, index)` throughout. `set_height` is the one place that says how tall a shelf stands — `layout`, the content total and `scroll_showing` all ask it, so they cannot disagree about where a shelf begins. Only the shelves the band reaches are measured; what it reaches part of is cut by `Prim::clipped`. An icon is a cell of the sheet `gfx` uploads once — raster art, the same at every scale, unlike the glyph atlas which is rebuilt per scale factor — drawn by `Prim::sprite`, a glyph prim with no tint, since the icons carry their own colors. The palette is the brush tool's own chrome: `app` builds it only with `Tool::Brush` in hand, so it comes and goes with the tool, and `Shift+B` shuts it without putting the brush down. `app` glides the list to the brush in the hand, edge-triggered on which brush it is, so taking one off a far shelf shows it while scrolling away does not snap back. `props` is the second half of that chrome: a bar under the strip carrying the name and `Property::BASIC`, and a chevron that drops the Advanced layout — the sections cut out of `Section::ALL` at `FIRST_COLUMN` into two columns, so a section added later falls into the second rather than off the bar. Closed and open never lay out the same property twice, which is why `Hit::Slider` names a field by its place and not by its property, and why `app` re-reads that place on every drag step — the bar may have folded under the pointer. A slider whose property is not `honored` is drawn in `theme.muted`: it still moves and still writes the brush, and the muting is the bar refusing to promise ink it cannot lay. The bar stands above the palette and the palette's `top` is the bar's bottom, so opening Advanced pushes the shelf down instead of covering it. A test measures every label and every range's top against the atlas, so no name in the bar is ever written with an ellipsis.
- **Stamping.** A brush does not sweep a line: it stamps a nib along one. `Tip` carries an `Option<Stamp>` — the pencil has none and goes on sweeping through `scene::swept_prims`; every brush has one and goes through `scene::stamp_prims`, which walks the flattened screen polyline and lays a dab where the press was, then one every `spacing` of Sketchbook's own spacing units of arc length, each worth `SPACING_UNIT` — a quarter — of the nib's width. What settles that quarter is Sketchbook's own help: it names 0.1 as "a very dense brush", 10.0 as the top, and 1.2 as the **Pencil's default**. A default pencil has to draw solid, and at a quarter of a width per unit 1.2 is 30% of a diameter — where every paint program's default spacing sits, and the ink pinches to only 95% of its width between two dabs. Read as whole widths that pencil's dabs would not touch at all; read as radii it would pinch to 80%, a beaded stroke, which is not what Sketchbook ships. The walk carries its leftover across the polyline's corners, so the spacing is the stroke's and not a span's; the tail past the last dab is not stamped, as in Sketchbook, and the nib's own radius covers it. `STAMP_STEP_MIN` floors the step at a pixel, so a hair-thin brush at the tightest spacing cannot lay tens of thousands of dabs. A dab is `Prim::dab`: a box `radius` px across and `radius * roundness` down, cornered by the smaller of the two — round when they are equal, a flattened capsule when they are not, which is as close to an ellipse as the box field comes — ramped over the same `feather` a swept stroke gets and turned by the nib's own angle. What the ramp *does* over that width is `doc::Profile`, Sketchbook's four tip profiles, carried to the shader as one exponent on the coverage in `Prim.falloff` — below one the nib stays full almost to its edge, above one it fades over the whole band, and one is the plain ramp everything that is not a nib is drawn with. Sketchbook does not document its curves; its own sets do, since every brush ships an Edge to go with its profile and the two move together (airbrush never past 0.28, regularSolid to 0.75, hardSolid at 0.88 to a brush, sharp from 0.89 up), so the profile is read in the order the sets themselves put it in. The clip is never bent: a soft shadow is still cut by a hard edge. A nib is never let vanish (`NIB_MIN_PX`), however flat it is squished. Flow is what one dab lays and opacity is the ceiling the pile reaches: `stamp_prims` puts the flow in each dab's own alpha, and `Frame::stroke` groups a stamped stroke as `Blend::Build` so the dabs meet one over the next. It follows that flow joins `Tip::is_direct`'s question — a nib that does not cover on its own must build in the scratch, or it would pile onto the board itself. The pen drives it too: `doc::Pressure` on the `Stamp` is how much of the size, the opacity and the flow a lighter touch takes away — Sketchbook names the two ends of each and the amount is the gap between them — and `doc::Envelope` on the stroke is what the hand actually did, readings from end to end spaced evenly along the stroke's own length, so a reading is asked for by how far along a dab lands and a curve can answer as well as the polyline it was fitted from. `Editor::Stroke::envelope` is the one that builds it, and both the live stroke and the release go through it, so the ink does not jump when the stroke is let go of; it keeps only what the nib can read, so a brush no pressure drives and a mouse both leave it empty. Under a lighter touch a dab is narrower, thinner, and closer to the next — the gap is a share of the nib's width, so the step shrinks with it and the ink stays as solid as it was. Flow driven by pressure joins `Tip::is_direct`'s question for the same reason opacity does: a dab that does not cover has to build in the scratch. A `doc::Scatter` throws each dab off true: its radius by so many world units and its angle by so many degrees — amounts in the unit of what they throw, which is how Sketchbook states randomness. The rhythm is never thrown; the gap is one of the three amounts whose scale the assets contradict. The throw has to be the same every frame, or the ink would shimmer: `dice` is splitmix64 over `(seed, dab index, salt)`, one salt per property so the throws do not track each other, and `seed_at` draws the seed from where the stroke *began*, in world units — never from the screen, which the camera moves, and never from anything that grows, since a live stroke and the path it is fitted into must scatter alike or the ink would jump at the release. The dab count is zoom-independent by construction (the step and the arc length both scale with `px_per_world`), so a dab keeps its own throw as the board is zoomed. A nib with no scatter skips the dice entirely. `Stamp::follow` is one of Sketchbook's four Rotation Dynamics: the walk adds the heading of the span a dab lands on to the nib's own angle. It is a `bool` and not the enum because it names what the canvas does with the *stroke* — a nib either runs along it or does not. The other two the stylus drives are not the nib's business at all: `Stylus::twist` resolves the lean (and, for `TiltAndRoll`, the roll on top of it) into one angle at the moment the sample is taken, and the stroke keeps it in its envelope beside the pressure — so the document records what the hand did rather than what the brush would have asked of a hand that is no longer there.

The pencil thins with the hand as well, and it is the only nib that does so while sweeping. A swept span is a capsule of one width, so `swept_prims` lays a taper as a run of them: each span of the flattened line is cut into as many capsules as it takes for the radius to move less than `TAPER_TOLERANCE_PX` across one, which is the same quarter pixel the curve was flattened to — the outline is as true to the hand as the line is to the curve. A stroke the pen never touched is one capsule a span, exactly as before, so the taper costs nothing when there is none. How much of the width a lighter touch takes away is `Tip::drive`: a brush says so on its own nib, where a slider reaches it, and the pencil has no sliders at all, so its answer is the build's `brush::PENCIL_DRIVE` and nothing new goes on disk — the document records what the person can vary, and there is nothing here to vary. The number is off the shipped sets rather than out of the air: not one of Sketchbook's 211 brushes drives its size fully, and its own Fine Art pencils sit between a quarter and two thirds, so half is the middle of that and a pencil at half is still a pencil at the lightest touch.

A nib may carry art of its own, and Sketchbook has two kinds that do quite different things. A **shape** is stamped in place of the round box; a **grain** is worn over one, which keeps its edge, its ramp and its profile and is eaten into. `scene::Shapes` is what `ImageSlots` is for a board's images — the sheet's slot, how it is cut up, and which cell each nib is in by the name a stroke calls it — and `Shapes::cell` hands back a `Cell` (a uv and a slot). `scene::Art` is what the walk is then given in its `Nib`, beside the radius, the ramp and the world-to-px the scatter is thrown by: `Round`, `Shape(cell)` or `Grain(cell)`. `Prim::shaped_dab` is a `KIND_IMAGE` box over the same rect the round dab would have filled, turned the same way, with square corners and no ramp, since the shape's own alpha is the only edge; `Prim::grained_dab` is `KIND_GRAIN`, which is the round dab exactly — corner, ramp and profile — with the cell's alpha multiplied into its coverage in the shader. The grain turns with the nib because it *is* the nib's; the canvas's own paper would stand still under it, and is not this. The sheet is full gray under its coverage, so `texel * ink` is the mark, exactly as the glyph atlas works. A stroke names its nib by name and never by cell: a board outlives the sheet it was painted from, and an index would move the day a set is added — a name this build does not carry lays a plain round nib rather than nothing, so a board painted elsewhere still opens. The shape is not part of the body a slider can reach, so it lives on `Preset`, not on `Brush`: `Preset::tip` is the one that knows every half of it, and `Library::tip` is what the editor is handed at the press. The nib is document data, not session state: `doc::Stamp` sits on `Path` and `Stroke`, absent on disk when the stroke was swept, and `Stamp::checked` refuses a board holding a turn of four hundred degrees or a gap of nothing — so a saved brush stroke reopens as the same ink and not as a sweep.

The **paper** is the third kind of art, and the one that is not the nib's at all. A grain turns with the dab because it belongs to the dab; a paper belongs to the board, so the nib is *dragged over* it — it stands still while the nib turns, and two strokes crossing one place meet the same fibres. The two are not alternatives: 49 brushes name a paper and 30 of those wear a nib as well, so one dab wears both, which is why `doc::Paper` sits on the `Stamp` beside `shape` and `grain` rather than inside a choice with them. It names the image, how wide one tile of it is in world units — a pencil's paper spans two hundred of them, a halftone's fifty — and how deep it bites; `Preset::paper` carries the first two, which no slider reaches, and the depth is the body's own `Property::TextureDepth`, at the bottom of whose track the paper is simply not there. The images ride on the same sheet as the nibs, in a band under them at `PAPER_PX` to a cell instead of a nib's 128, because one tile covers hundreds of world units and a stroke crosses only a handful of its texels; one sheet is what makes a dab wearing a nib and a paper one draw instead of two. `Shapes::paper` hands back that cell drawn in half a texel on every side, since a paper is the one thing sampled by *wrapping* — without the inset the seam blends with the cell next door and the tiling shows as a grid. `scene::Weave` is how it lies under the window: screen px into tiles, and where world zero falls, wrapped into the one tile it is in on the CPU and in f64, because `fract` of a camera a million units from the origin has no precision left to give. `Prim::papered` puts it on a dab of any kind and takes the sheet's slot with it, which is why `Prim::samples` and not the kind is what cuts a run — a papered round dab is a plain box that nonetheless reads a texture, and a run that bound the blank instead would sample white and never bite. `PAPER_MIN_PX` floors a tile at a couple of pixels, so zooming out stops the weave getting finer rather than turning it into noise that changes as the board moves.

`brush::ring_prims` is the pointer's promise, and it says what the nib is rather than only how big: `ring_of` reads the body for how far the nib reaches each way and how far it is turned, and the ring walks the same rounded box `Prim::dab` fills — four arcs about the corners' own centres, which collapse into one circle when the nib is round. It traces the nib's shape and not its art, since tracing an alpha mask every frame is a different job and the ring is there to say how big and which way round.

What the importer will not read is Sketchbook's brightness and contrast on a paper. They go where the three randomness amounts went: nothing says what the numbers mean, and the one band they could plainly be — the -100..100 every such control uses, and that ImageMagick's own takes — turns eight of the 49 papers solid black, one of them under a brush named Textured Pencil. A brush that paints nothing is not what anybody ships, so the reading is wrong and the canvas does not guess. The invert is a flag and says exactly what it means, so it is baked into the cell: the same TIFF used both ways is two cells under two names, which is how 30 images become 32 cells.

- **The Omarchy theme.** The board wears what the desktop wears, and reads it from the same files every other app on the desktop does. `omarchy::read` takes `~/.local/state/omarchy/current/theme/colors.toml` and `shell.toml`, with the person's `~/.config/omarchy/shell.toml` laid over the second, plus two things that belong to the session rather than to the theme — the face `fc-match` resolves `monospace` to and Hyprland's `decoration:rounding`. Only those five reads are shell; the parsing is pure and carries the tests, and it runs the same alias cascade `omarchy-theme-color` documents, because a theme installed from a repo may carry nothing but the ANSI names and is still a theme. Nothing here fails: a board that will not open because a theme file is missing would be worse than one drawn in its own colours. What a machine without Omarchy sees falls out of one split — **the palette and the text size come from the theme, so they need one; the face and the corner come from the session, so they apply wherever the session answers** — which is exactly the seam `Theme::from_style` makes when it lays `wearing` over a palette or over the board's own.

  Omarchy paints every surface in `background` and separates it with a **border** — its bar, menus, popups and tooltips all name the same one, and `shell.toml` carries fill *alphas* rather than surface shades. That does not close on a board, whose canvas *is* the ground: a dock painted in `background` over a canvas painted in `background` is invisible but for its outline. The desktop already names the way out — **the canvas is `dark_background` and every panel is `background`** — which is a step apart whichever way a theme runs, and which on the `white` theme lands on the very palette the reference look was drawn as (`#f5f5f5` under `#ffffff`). The rest goes by the section each surface plays: the strip is `[bar]`, the floating panels are `[menu]`, what is inside them is `[controls]`. `muted` stops being a mix this build invented and becomes the token the theme names; `active_bg` is the ink at `selected-fill-alpha` **composited on the CPU in sRGB**, because a fill alpha over a surface is what Omarchy means by it and sRGB is where the number was chosen — the same fraction taken in linear light comes out half again as bright. The dock's inks do not move at all: they are what a board is *marked up* in, not what the interface is painted with, and nothing about a theme reaches `theme::INKS`. `lifted` stays the fixed blue, for the reason it was fixed.

  A theme is not only colours, so `Theme` carries two numbers that are not: `border_px` (`[controls] normal-border-width`, its first value where the shell writes a CSS-style list, since a rounded rectangle here has one width) and `rounding`, Hyprland's own against the 8 the chrome was drawn to. They ride there because a radius and a border are only ever read while painting and every `prims()` already takes a `&Theme` — so the desktop reaches all six chrome modules without one signature changing. `Theme::corner(radius, scale)` and `Theme::edge(scale)` are the two doors. At a rounding of 8 nothing moves; at Omarchy's own 0 the chrome goes square like every window around it. **A capsule is not a corner**: a slider's track, a scrollbar's thumb, an ink dot and a round knob keep a radius that is half their own height, and squaring those would not look like Omarchy, it would look broken. The layers handle is not one of them — it is a surface, painted like the panel it opens and standing right beside it, so the desktop's corner reaches it too; what it keeps is a ceiling, never rounding past the capsule a tab that narrow already is.

  Type is the face at one size, because the chrome draws one size: `Font::from_file` off `fc-match`, the bundled Liberation Sans still the fallback for a file that will not open or parse, and `[font] base-size` in place of the 13 compiled in — but only where a theme was found, so a machine without one letters itself at `tabs::LABEL` as it always has. `[spacing] scale`, times `base-size / 12` when `scale-with-font` is on, is `App::chrome`, folded in exactly where the window's scale factor already was: the canvas, the grid and the selection handles keep the window's alone, since panel density is not zoom.

  A change arrives two ways, and the first asks nothing of anybody: `focus_gained` compares the mtime of `theme.name` and re-reads when it moved, which is the moment the theme switcher gives the keyboard back. The other is `omawhite --theme`, which never opens a window — over the socket it is `op: theme` with `colors` made **optional**: with colours the plugin is dressing the board in its own three, without them the desktop's theme is to be read again. The schema stays closed either way; an optional field is a declared field. `App::restyle` is the one door both go through. `ensure_atlas` runs at the head of every frame and builds whatever the theme and the scale factor now name, because `frame` only reads — an atlas nobody put back leaves every lettered surface (the tab strip, the layers panel and its handle, the brush strip, the brush library, the properties bar) drawing nothing at all. It guards on the **size**, and that is what decides which half of a restyle is paid: a theme set moves colours, so the face is compared before it is read and an unchanged one is not parsed again — the desktop's `monospace` is a Nerd Font, and parsing megabytes of outlines on the loop thread was the whole of the pause a theme change used to cost. Measured over ten real `omarchy-theme-set` runs, the face resolved to the same file every time and the parse alone was 51–70 ms in release and 328–350 ms in debug, against 14–24 ms for the whole of the rest — which is itself almost all the two subprocesses `omarchy::read` spawns, and one of them is the `fc-match` that answers whether the face moved at all. A face that *did* move drops the atlas by hand, since a size guard cannot see a new face at the old size. The hook that calls it ships in `contrib/omarchy/` and is installed by hand — the board does not write into `~/.config/omarchy` on its own, for the same reason a draft's autosave never writes into a file the person named.

- **Ink.** Every stroke names its colour on disk and always has; what was missing was a way to choose one. The inks are `theme::INKS`, a **constant**: black, white, and five colours, and no part of a theme reaches any of them. That is the whole point — a board is a document, so ink picked today has to be the same colour tomorrow, and a palette that moved when the desktop did would quietly break that. The first slot used to be the theme's own foreground and was the one thing that did move; it is black now. What the canvas still answers is which ink a board is **born** holding (`Theme::first_ink`): a black pencil on a dark ground draws a line nobody can see, so a dark canvas opens on the white and a light one on the black. Asked once, at birth — a theme set later leaves the ink in the hand where it is, the way it leaves the tool. Every swatch wears the chrome's own hairline, because on any theme one of the two neutrals is the colour of the panel under it and would otherwise be a slot nobody can see or aim at. They live in the dock rather than on the brush's own bar, because the pencil lays ink too: the ink is the window's, like the tool in the hand. `app` keeps which one by index and answers `ink_hex` for the document and `ink_rgba` for the canvas and the brush's ring.
- **Units:** world unit = logical pixel at zoom 1; `View` folds the window scale factor in. Dock, panels, grid and selection handles are sized in logical px; brush size is world units, so it scales with zoom like the ink it makes.

# Security Invariants

Verified by tests; don't loosen them casually:

- IPC schema is closed (§5): unknown op, field, or version is an error, never best-effort. One JSON per line, frames capped at 64 KiB, socket `0600`, same uid only.
- Disk (§9.3): `~/.local/share/omawhite` and subdirs `0700`, files `0600`, writes are atomic (tmp in same dir + rename).
- Export destinations arriving over the socket or CLI are candidates; the binary validates them against the allowlist (§8.2) before writing. A path that came back from a portal dialog is not one of those — it is the user's own choice, made in a system dialog — so save/open paths are not measured against that list. Loading one changes nothing about the parse: schema closed, every blob still checked.
- An `image` element's `blob` is a bare lowercase-hex sha256 — checked when the board parses and again before it becomes a path. Pasted bytes are refused past 8192 px a side, read from the header before any texel is allocated.
- What the export dialog writes into a live terminal (§9.4): the instruction is printable characters and newlines only — no ESC, no carriage return, no tab, no other C0 — capped at `PROMPT_MAX`, refused rather than stripped, and pasted bracketed, where a newline is a line of the message and never an early submit. The only thing ever typed as keys is a skill's call, `/` or `$` and a name `skills::callable` passed; neither reaches a shell, going as an argument to herdr or through `tmux send-keys -l` and a buffer on stdin.
